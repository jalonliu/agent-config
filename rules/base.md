# Base Rules - 共用底座

## Context 与 Loop 核心原则

1. **Context is All You Need**：输出质量大半在开口之前就定了
2. **Loop 闭环进化**：有日志、有记录可以复盘，改完之后能验证结果
3. **珍惜上下文窗口**：每个注入的内容都要回答"它凭什么在这里"

## 分层架构

```
主脑层：base + by-tool + by-role → 拼接 → 全局规则文件
执行器层：base + 工具段 + 任务卡 → 现场渲染 → 执行器上下文
```

## 上下文预算

| 层级 | 上限 | 说明 |
|------|------|------|
| 主脑侧 | 24KB | 每次会话开场占用 |
| 执行器侧 | 12KB | 任务卡渲染后 |

## 规则治理

- **加法**：新规则需说明解决的问题
- **减法**：淘汰规则需记录原因和替代方案
- **验证**：任何判据先喂负样本确认会变红

## 多工具适配

- 不按模型分规则，按"工具 × 角色"分层
- 执行器优先用 Pi（上下文可完全定制）
- Flash 级模型已跨过 Coding 基准线，执行层质量差异不大

## Advisor 模式

- 用全方位能力强的模型做高价值判断
- 给顾问干净的独立上下文（不背会话历史）
- 顾问意见同样需要验证

## 记忆管理

- 跨 Agent 记忆存放在 `memory/` 目录
- 格式：Markdown 文档 + 索引
- 小项目不用 Memory，以代码库为准

## 行为轨迹

- 所有 Agent 行为数据长期保存
- 用于复盘、回测、追溯历史决策
- Claude Code 默认 30 天删除，需修改配置：`claude config set telemetry.enabled true`

## Skill 优先级

1. 吸收内化到工作流
2. 装到项目目录
3. 全局安装（仅高频通用）

## MCP 原则

- 有 CLI 就用 CLI
- MCP 项目级别控制
- 非必要不开
